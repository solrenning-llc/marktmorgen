### LOW: independent rate sensitivities are not disjoint supplier components

At decision lines 84–107 the three independent zero-rate differences are
presented as Redis command, transfer, and storage components and summed. They
reproduce, but the model is not linear in those rates. The `store-readings`
line selects a maximum of two read shapes (`tests/plan-cost-registry.ts:1174`),
and `free-share` carries the same interaction. Changing one rate can change
the selected shape and consequently the non-Redis costs included in the
difference. A difference divided by the command price is therefore not an
exact modeled command count either.

The sum of three separate sensitivities exceeds the joint sensitivity by
`$0.007206469632` per month for each plan. The independent sums are
`3.9055815226132777 / 5.819388372863283 / 9.274566588363285`; the joint
differences are `3.898375052981277 / 5.812181903231274 / 9.267360118731283`.
The diagnostic prints the responsible model lines rather than assuming the
joint difference is itself an exact supplier invoice.

Suggested correction: describe these figures explicitly as conservative
rate-sensitivity sums, remove the implied exact command counts, or implement
an attribution that retains the chosen operation's resource vector. The
comparison is conservative and still favors PAYG, so this has no demonstrated
effect on the decision and is LOW.
