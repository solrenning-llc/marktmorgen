C4-20261106-0700-C5-27 condition (1) requires an invalid supplied color to be refused without writing. Dropping the field satisfies a weaker contract than that decision.

The independent proof uses the actual authenticated route, session, catalog and picture-door implementation with the existing `failure-cleanup-world.ts` in-memory file-provider fixture. The proof does not show CSS injection, unauthorized access, a provider request, loss of funds or an unbounded operation.

Route proof: 13 assertions, 6 failures and 7 passing controls. A trailing-newline strict-pattern hypothesis was tested and discarded: the real pattern correctly rejects it.

Correction: distinguish omitted tone from a supplied invalid tone and refuse the latter before attachment writes (preferably before optional provider work). Preserve old-picture compatibility and ownership/door checks. Add permanent actual-route cases and rerun this unchanged proof. Alternatively, C4 must explicitly change condition (1); reviewer silence is not that decision.

### L2 — Downsampling cannot establish that the image has no transparency

`components/shrink-image.ts:75–83` checks alpha only after reducing the canvas to 16×16. A small transparent area can disappear through sampling/rounding. The code and PR claim that any transparency produces no color, so the color never shows through the loaded image.

The browser proof bundles the actual `shrink` function and runs it in native Chromium, offline. It creates synthetic PNG inputs, calls the real shrink/encode path, decodes the returned WebP, and counts every decoded alpha byte:

| Input | Decoded transparent pixels | Returned tone | Result |
| --- | ---: | --- | --- |
| Opaque 1024×1024 | 0 | `#336699` | control passes |
| One transparent pixel at (511,511) | 1 | `#336699` | expected null; fails |
| Transparent 64-pixel stripe | 65,536 | null | control passes |
| JPEG control | 0 | `#336699` | control passes |

This is a small visual-contract regression, not an access or payment issue. The proof establishes a transparent pixel in the actual encoded output, not merely the input canvas. No external browser requests occurred.

Correction: establish opacity from the full bounded output canvas before generating the small average sample, or conservatively omit tone whenever opacity cannot be established. Keep the work in the creator's browser, bound it by the existing shrunk dimensions, and preserve JPEG flattening/old pictures. Adopt an actual-canvas permanent regression and rerun this unchanged proof. Do not replace it with a test of `toneOf` alone; that helper correctly handles the bytes it receives, while the loss occurs before it is called.
