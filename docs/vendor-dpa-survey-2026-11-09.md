# Suppliers that process personal data: DPA survey (November 9, 2026)

Coordinator order C1-20261109-1610-TODOS-73, item 4: list, without contracting anything, every supplier that processes personal data for Marktmorgen, its official data processing agreement page, whether that agreement is already in effect, and who has to accept it. Accepting any term is the owner's alone.

**What this survey is and is not.** It reads only public pages and this repository. No account was opened, no term was accepted, no form was sent and nobody was contacted. We cannot see the owner's accounts, so this document never says that the owner has already accepted anything: wherever a page says an agreement takes effect by using the service, the status still reads "the owner confirms in the account". A public agreement shows what a supplier offers, not that the owner's account is covered, nor that Marktmorgen complies. It updates, and does not replace, the earlier record [docs/current-provider-transfer-evidence-2026-10-27.md](current-provider-transfer-evidence-2026-10-27.md).

## Method

1. **Inventory from the code on `origin/main` at 0e8b8c6b53** (November 9, 2026): the environment variables read by `app/`, `lib/` and `components/` (for example `UPSTASH_REDIS_REST_URL`, `RESEND_API_KEY`, `R2_ACCOUNT_ID`, `BACKUP_R2_BUCKET`, `BUNNY_STREAM_API_KEY`, `ANTHROPIC_API_KEY`, `STRIPE_SECRET_KEY`, `PAYPAL_PARTNER_CLIENT_ID`, `DISCORD_CLIENT_ID`, `META_APP_ID`), the packages imported (`@vercel/blob`, `botid`), the provider hosts called (`api.stripe.com`, `api-m.paypal.com`, `api.resend.com`, `email.<region>.amazonaws.com`, `sns.<region>.amazonaws.com`, `r2.cloudflarestorage.com`, `video.bunnycdn.com`, `api.anthropic.com`, `www.googleapis.com`, `api.zoom.us`, `graph.microsoft.com`, `graph.facebook.com`, `discord.com/api`), the privacy policy (`app/privacy/page.tsx`, the section "We share information only with") and `lib/person-data.ts`.
2. **Official pages read on November 9, 2026** (about 16h30 Fortaleza) with WebFetch, and with `curl` through the session's proxy where WebFetch could not resolve the host. TLS verification was never turned off.
3. **Hosts the session's network refused** (the proxy answered 403 to the connection, so the page was not read today): `resend.com`, `www.resend.com`, `aws.amazon.com`, `d1.awsstatic.com`, `www.zoom.com`, `zoom.us`, `workspace.google.com`, `developers.google.com`, `policies.google.com`, `business.safety.google`, `slack.com`, `www.facebook.com`, `developers.facebook.com`, `www.paypal.com`, `support-dev.discord.com`, `unsplash.com`. For those, the status is "unknown" unless the October 27 record already read the page, which is then cited with its own date.

Status words used below, and only these:

- **In effect by use, per the page**: the page says the agreement forms part of the terms the customer accepted to use the service. The owner confirms in the account (entity, plan, product).
- **Needs the owner to accept or sign**: the page says the agreement takes effect when the customer signs it, accepts it or completes it.
- **Unknown**: the page could not be read today, or it does not say.

## Limits

- Reading a page is not accepting it, and an offer on a public page is not proof of the account's coverage, entity, region or subprocessors.
- DPF certification needs the government register (dataprivacyframework.gov), not read here; this document only repeats what each supplier's page says about itself.
- Whether a configured variable is actually set in Production was not checked; the October 27 record lists the Production variable names without values.
- Brazilian law (LGPD, ANPD Resolutions 19/2024 and 32/2026) is covered in the October 27 record; this survey adds nothing there.
- No price, limit, commission, flag or gate changes. No cost is added: each owner action above is a look inside an existing account, and any paid step stays under FX275, where an unknown cost fails and is never zero.
